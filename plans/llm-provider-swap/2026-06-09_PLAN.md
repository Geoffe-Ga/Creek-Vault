# Plan: Swappable LLM providers (Anthropic / OpenAI / Gemini), keys discovered from the environment

- **Date:** 2026-06-09
- **Branch:** `claude/gemini-openai-api-config-sefrii`
- **Status:** Proposed (analysis + decomposition; no code yet)

## Goal

Let an operator select the cloud LLM backend — Anthropic, OpenAI, or
Google Gemini — for both `creek-tools` (classification + author desk)
and CrawDad (Discord bot), via a single config string per package. API
keys are **discovered from the environment by each provider's SDK** and
are **never written into this repository, any config file, logs, or
error messages**. Ollama (local) remains the default for `creek-tools`.

## Non-negotiable constraints

1. **Keys live only in env.** No `api_key` field on any config model.
   Each SDK reads its conventional variable:
   - Anthropic → `ANTHROPIC_API_KEY`
   - OpenAI → `OPENAI_API_KEY` (optionally `OPENAI_BASE_URL`)
   - Gemini → `GOOGLE_API_KEY` (or `GEMINI_API_KEY`)
2. **Error redaction preserved.** Native SDK exceptions are re-raised as
   `RuntimeError(type(exc).__name__)` so request state (which can carry
   the key in headers) never leaks. This pattern already exists in
   `AnthropicProvider.call_with_metadata`; every new provider mirrors it.
3. **Cloud-egress consent generalises.** The existing
   `CREEK_ANTHROPIC_CONSENT` gate (and `ANTHROPIC_CLOUD_WARNING`) is
   about "fragment content leaving the device" — true of any cloud
   provider. It becomes provider-neutral; Ollama stays exempt.
4. **No model-ID literals outside config modules.** CrawDad already
   enforces this (`tests/test_no_model_literals.py`); new
   `gpt-*` / `gemini-*` defaults stay confined to config and the test is
   extended to cover them.
5. **Quality bar unchanged:** branch coverage ≥90%, docstrings ≥95%,
   complexity ≤10/function, mypy strict, ruff/bandit clean — in both
   packages.

## Key architectural decision: keep the packages decoupled

CrawDad and `creek-tools` are **siblings** (FEAT-013). CrawDad imports
**nothing** from `creek-tools` today — it talks to it only over the MCP
stdio protocol (it spawns `creek-tools-mcp` as a subprocess). That clean
boundary is worth preserving.

**Decision:** Do **not** introduce a shared `creek.llm` package or any
Python dependency edge between the packages. Instead, build **two
parallel, independent provider abstractions** that mirror each other's
structure:

- `creek-tools`: a **synchronous** provider abstraction (the pipeline is
  sync: `anthropic.Anthropic()`, `httpx.Client`).
- CrawDad: an **asynchronous** provider abstraction (the bot is async:
  `anthropic.AsyncAnthropic`).

DRY is satisfied **within** each package (one factory, one Protocol,
providers swapped by a config string). The cross-package overlap is only
the *shape* — a normalized `Completion` type and a `complete()` contract,
~30–40 lines of thin wrappers per provider. We keep the two honest by
mirroring names and the normalized response shape, not by sharing a
module. **Trigger to revisit:** if the duplicated provider bodies ever
grow real logic, extract a shared package then — not now.

The sync/async split, which would have been a wrinkle for a shared
package, becomes the natural seam: each package implements the idiom it
already uses.

## Design — per package

### Shared shape (mirrored, not shared)

```
Completion            # normalized result: text, stop_reason, usage|None
LLMProvider (Protocol)# .model, .available, .complete(prompt, *, max_tokens, system) -> Completion
build_provider(cfg)   # factory: provider string -> concrete provider
```

`creek-tools` already has the right normalized type: today's
`AnthropicCompletion` (`text`, `stop_reason`, `usage`). It is renamed
`Completion` (with a deprecated `AnthropicCompletion` alias so the public
`creek.classify.llm` shim and downstream callers keep working).

### creek-tools (synchronous)

```
creek/classify/llm/
  completion.py          # Completion (was AnthropicCompletion) + alias
  base.py                # LLMProvider Protocol
  providers/
    __init__.py          # build_provider() registry/factory
    anthropic.py         # existing AnthropicProvider, normalized
    openai.py            # new (sync openai SDK)
    gemini.py            # new (sync google-genai SDK)
    ollama.py            # existing call_ollama wrapped as a provider class
```

- `orchestrator.py`: replace the four `config.provider == "anthropic"`
  branches (`__init__`, `_check_availability`, `_invoke_llm`,
  `invoke_prompt_with_metadata`) with one `build_provider(config)` call;
  `LLMClassifier` delegates `available` / `complete` /
  `complete_with_metadata` to the provider. Net simplification.
- `author/client.py`: `AuthorLLMClient.from_config` calls
  `build_provider(config)` instead of constructing `AnthropicProvider`
  directly. One-line swap; `resolve_voice_model` is already neutral.
- `config.py` `LLMConfig`: extend `provider` docstring to list `gemini`;
  add optional `api_base: str | None = None` (OpenAI-compatible
  endpoints — Azure / vLLM / OpenRouter — without new providers). **No**
  `api_key` field. Per-provider `DEFAULT_MODEL` moves into each provider
  class (generalising today's `_OLLAMA_DEFAULT_MODEL == "mistral"`
  sentinel so `provider: openai` with no `model` still resolves).
- `pyproject.toml`: add `openai` and `google-genai` as **optional
  extras** mirroring the existing `[anthropic]` extra; fold into `[all]`;
  regenerate `uv.lock`; update `requirements*.txt` fallbacks.

### CrawDad (asynchronous)

```
crawdad/crawdad/
  llm/
    __init__.py          # build_async_provider() factory
    base.py              # AsyncLLMProvider Protocol + Completion shape (mirrored)
    anthropic.py         # AsyncAnthropic wrapper (extracted from router/composer shape)
    openai.py            # new (async openai SDK)
    gemini.py            # new (async google-genai SDK)
```

- `config.py`: add `llm_provider` (env `CRAWDAD_PROVIDER`, default
  `anthropic`); replace the eager `ANTHROPIC_API_KEY` requirement with a
  **provider-conditional** env check (require the key matching the
  selected provider). Prefer **not** storing the key on `CrawDadConfig`
  at all — let the SDK read it — removing a secret from a frozen object
  passed around the app. Add per-provider router/composer model defaults
  (Haiku-tier vs Sonnet-tier mapping), still confined to `config.py`.
- `cli.py` `_build_agent_components`: replace
  `anthropic.AsyncAnthropic(api_key=...)` with `build_async_provider(...)`.
- `router.py` / `composer.py`: call through the `AsyncLLMProvider`
  abstraction instead of the raw `self._client.messages.create(...)` /
  `except anthropic.AnthropicError` shape. Heaviest single change.
- `pyproject.toml`: `anthropic` stays; add `openai` + `google-genai`
  (optional extras or direct — match the package's existing style).
- `tests/test_no_model_literals.py`: extend to forbid `gpt-*` /
  `gemini-*` literals outside `config.py`.

## Security review

- ✅ Keys never in repo/config: enforced by the absence of any `api_key`
  field; SDKs read env. Document the env-var matrix in both READMEs.
- ✅ Error redaction replicated in every new provider (constraint #2).
- ✅ Consent gate generalised to cover OpenAI/Gemini egress (#3).
- ✅ `detect-secrets` pre-commit + `.gitignore` already keep `.env`-style
  files out; no change needed, but verify the baseline after adding deps.
- ⚠️ `api_base` override is attacker-relevant only if an untrusted party
  can write the config; CrawDad already declares `crawdad.yaml` a trusted
  trust boundary, so this is consistent. Note it in the ADR.

## Testing

- Mirror the existing SDK-mock pattern (`tests/test_classify.py` mocks
  `anthropic`) for OpenAI and Gemini: env-missing → `RuntimeError`,
  response → normalized `Completion`, error redaction, model resolution.
- Factory tests: each provider string → correct class; unknown → clear
  error.
- CrawDad: async-mock router/composer against each provider; extend the
  no-model-literals test.

## Sequencing (tracer-code; each step ships green)

1. **#1** Normalize `Completion` + `LLMProvider` Protocol (pure refactor).
2. **#2** Factory + route orchestrator & author client through it
   (Anthropic/Ollama only). Removes scattered conditionals.
3. **#3** Generalise the cloud-consent gate (provider-neutral).
4. **#4** `OpenAIProvider` (sync) + dep + tests.
5. **#5** `GeminiProvider` (sync) + dep + tests.
   → creek-tools is now fully swappable.
6. **#6** CrawDad async provider abstraction + factory (Anthropic only,
   refactor router/composer onto it). Pure refactor, green.
7. **#7** CrawDad OpenAI + Gemini async providers + config selection +
   per-provider model defaults + no-model-literals test extension.
8. **#8** Docs: both READMEs (env-var matrix), `CLAUDE.md` config
   sections, an ADR recording the decoupling decision.

Steps 1–5 are low-risk, high-leverage, and land independently of
CrawDad. Steps 6–7 carry the real surface area (async + the
Anthropic-shaped router/composer). Step 8 closes the loop.

## Open question to ratify before coding

The decoupling decision above (no shared package) is the load-bearing
choice. Everything else follows from it. If you'd rather pay the coupling
cost for zero duplication, steps 1 and 6 collapse into one shared module
and CrawDad gains a `creek-tools` dependency — but that punctures the
sibling boundary and is **not** recommended.
