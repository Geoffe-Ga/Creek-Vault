## Synthesis

**The most consequential delta is the audit-artifact gap, not the embedding question.** Graphify ships `GRAPH_REPORT.md` as a primary deliverable; Karpathy's pattern centers on `index.md` plus `log.md`. Creek Vault has neither — five separate emergence reports run on different cadences with no unified document an agent or human can read to understand what's in the vault. This is the simplest single thing the project is behind on, and it's not philosophical; it's a missing artifact. The integration plan treats this as a v1 deliverable.

**The most surprising delta is paradox preservation.** Creek treats contradiction as data; both Karpathy's lint pass and Graphify's confidence-tier model treat contradiction as something to flag and resolve. AlfredOS's Distiller "surfaces implicit assumptions and contradictions" without a clear stance on what to do with them. None of the reference systems has Creek's polygnostic framing. This is the *philosophical* delta that must be defended throughout integration — every borrowed pattern (lint, audit report, edge confidence, four-worker decomposition) must be adapted to *route* contradictions to `10-Liminal/Paradoxes/` rather than to flag them for cleanup.

**The most consequential delta that looks surprising but isn't is the "no embeddings" question.** Graphify makes a large rhetorical move out of "no embeddings, no vector DB"; Karpathy's pattern at personal scale (~100 articles) doesn't need embeddings. But these are different claims. Graphify's "no embeddings" means *similarity-as-graph-topology* rather than vector search. Karpathy's "no vector DB" means *index-driven navigation* at small scale. Neither is in tension with Creek's embedding-based resonance — Creek can adopt topology clustering as a *complement* (Leiden over the resonance graph) without giving up cosine similarity, and can adopt index-driven navigation in the compiled layer without giving up embedding-based resonance discovery underneath. The user's stated decision to keep embeddings is correct and not threatened by either reference system.

**The wavelength gap dwarfs everything else.** None of the reference systems has any phase concept. Graphify clusters topologically; Karpathy's lint resolves contradictions; AlfredOS's Surveyor finds relationships; Dontoh's Alfred decays memories temporally. None of them tracks where the human is on a developmental cycle. The voice-skill tree, the wavelength-phase mining strategy, the dosage-aware paradox detection — these are all infrastructure no reference system has, and the integration plan must explicitly preserve their first-class status. Phase awareness is not a tag taxonomy; it's the lens through which every other tag is read.

**The compile-then-query commitment is where the most leverage is.** Of all the patterns in this matrix, the single change with the most downstream impact is committing to Karpathy's discipline: the compiled layer becomes the canonical query target, queries don't go directly to fragments, good answers file back into the compiled layer, and `creek lint` runs on a cadence to keep it healthy. Most other candidates either prepare for this (deterministic-first ingestion, audit reports, four-worker decomposition) or follow from it (CrawDad querying the compiled layer, voice-skill tree feeding the index).

**The CrawDad agent-layer gap is structural and deferrable.** AlfredOS's `alfred-vault` and Dontoh's Alfred between them define a credible CrawDad architecture — six layers (Interface/Agent/Kinetic/Semantic/Data/Infra), four background workers (Curator/Janitor/Distiller/Surveyor), Haiku-router/Sonnet-composer split, MCP-as-capability-surface, Jig-style workflow DSL. The gap isn't a research question; it's an implementation question. v1.0 should land the MCP surface and the conversational agent loop; the workflow DSL and four-worker cadence can come in v1.1.

**The drift between ontology spec and `creek-tools` implementation is a v1.0 prerequisite.** As flagged in `LANDSCAPE.md`, `creek-tools/docs/classification.md` documents phase names ("Origins / Cresting / Receding / Composting") and mode names ("solo / dialogue / reflective / analytic") that don't match the canonical spec ("Rising / Peaking / Withdrawal / Diminishing / Bottoming Out / Restoration" and "Inhabit / Express / Collaborate / Integrate / Absorb"). Frequency names also drift — `creek-tools/docs/` references `amplitude` and `pitch` instead of the spec's APTITUDE F1–F10. Compile-then-query is downstream of having one source of truth for the most load-bearing taxonomy in the system. This needs reconciliation before — not after — the Karpathy adoption work begins. **Tracked as [`INC-019`](../git-issues/INC-019-spec-impl-drift-phase-mode-frequency-taxonomy.md) / [GH #201](https://github.com/Geoffe-Ga/Creek-Vault/issues/201).**
