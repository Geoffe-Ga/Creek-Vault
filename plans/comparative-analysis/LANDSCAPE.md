# Landscape: Creek Vault + CrawDad in the Personal Knowledge Graph Field

**The strategic question this analysis answers:** Given that Karpathy's compile-then-query pattern, Graphify's topological extraction, and the AlfredOS/Alfred lineage of agent layers have all converged on adjacent territory in the last six weeks, what does Creek Vault + CrawDad keep, what does it borrow, and what does it refuse — without losing the wavelength-aware, voice-fidelity, paradox-preserving identity that makes the project worth building at all?

## Four systems, four categories, not all the same kind of thing

It is tempting to line these up as competitors. They aren't. **Creek Vault is a phase-aware knowledge ontology with an opinionated voice-generation pipeline.** It treats fragments as the primary unit and resonances as the relational substrate, with a wavelength layer that interprets *all* other content. **CrawDad is a Discord-first spiritual-companion agent**, planned, that consumes that vault and reflects, drafts, and sounds-boards. **Graphify is a code-first knowledge-graph extractor**: it lives inside coding agents, treats source files as the primary unit, and produces a NetworkX graph plus an audit report that the agent reads before its tool calls. **Karpathy's "LLM Wiki"** is barely a system — it's an architectural commitment with a folder structure (`raw/`, `wiki/`, `CLAUDE.md`) and a discipline (compile per-source, query the wiki not the raw, file good answers back, run a lint pass on demand). **AlfredOS** is two things wearing the same name: a no-code SaaS-replacement bundle on top of n8n flows for solopreneurs, and `alfred-vault`, a more serious six-layer Python project with four background workers tending an Obsidian vault — closer to CrawDad's territory than to Creek's. **Dontoh's Alfred**, the dev.to sidebar, is a clean specification of a two-LLM agent loop (Haiku for tool-routing, Sonnet for composition) inside a single developer's stack.

Mapped onto the project: Karpathy is the closest neighbor to *Creek Vault's* compiled-layer ambition; Graphify is the closest neighbor to its *extraction* ambition; AlfredOS-`alfred-vault` and Dontoh's Alfred are the closest neighbors to *CrawDad's* agent-layer ambition. None of them is a phase-aware knowledge system, and none has a voice-skill tree. That is Creek's air to breathe.

## Where the pair is strong, where it's behind

Treated as complements — Creek produces the data, CrawDad consumes it for Discord-mediated interaction — the project's strengths are real and load-bearing. The **wavelength infrastructure** (six phases × five modes × Do/Feel × Medicine/Toxic, applied to ten APTITUDE frequencies) is more semantically precise than anything in the reference set. None of Graphify, Karpathy's pattern, AlfredOS, or Dontoh's Alfred has a phase concept at all — and a phase-aware lens isn't something one bolts on retroactively. The **paradox preservation infrastructure** (`10-Liminal/Paradoxes/`, the four detection rules, the explicit policy not to resolve contradictions) is genuinely distinctive; Karpathy's lint pass actively *flags* contradictions as defects, which is the opposite stance. The **embedding-based resonance system** is doing real semantic work — finding wavelength-phase connections between texts that share no surface vocabulary — that Graphify's topology-only model can't replicate, and that Karpathy's `index.md` lookup doesn't even attempt. The **voice-skill tree** is a primary deliverable in Creek's spec; it has no analog in any reference system, and the closest community implementations of Karpathy's pattern explicitly cede the "voice, narrative, audience empathy" mile back to humans. The **emergence infrastructure** as a whole — Unnamed Digest, Synchronicity Detection, Compost Tracking, Tag Garden, Paradox Preservation — is more coherent than the bolt-ons in any reference system, even though, at present, these five are implemented as separate report types rather than as facets of a single operation.

Where the pair is behind: the **compiled layer is aspirational, not committed**. The Threads/Eddies/Frequency-index notes are *generated*, but queries don't route through them; downstream consumers (mining, drafting) still hit fragments directly. Karpathy's pattern is operationally simpler than Creek's *and* commits to compile-then-query; Creek has the harder ontology and the weaker discipline. The **audit-report-as-artifact** pattern (Graphify's `GRAPH_REPORT.md`) has no Creek equivalent — there is no single document an agent or human can read to know what's in the vault. The **agent-layer scaffolding** is entirely missing — CrawDad doesn't exist yet, and neither does the MCP surface that would expose creek-tools to it cleanly. **Multimodal scope** is narrower than Graphify's: images via OCR, but no video/audio transcription. And the **maintenance loop** is fragmented — Creek has Tag Garden, Unnamed Digest, Synchronicity, Compost, and Paradox running as five separate cadences with no unified `creek lint` command, when in practice the user thinks of them as facets of the same vault-hygiene operation.

## Values vs. mechanics: what's movable, what isn't

Most of the deltas in this analysis are mechanics. Whether resonances are written to frontmatter or to a NetworkX graph is a representation choice; whether the compiled layer is per-source or per-eddy is an organizational choice; whether the agent uses Haiku or Sonnet for intent extraction is a cost-tuning choice. These are all up for negotiation and the integration plan moves several of them.

The non-mechanical differences — the philosophical ones — are where the integration must hold the line. Wavelength tracking is not a tag taxonomy that other systems are missing because they haven't gotten around to it yet; it's a different mental model of what knowledge *is*. Paradox preservation is not a lint-pass exception; it's a stance about polygnostic experience that Karpathy's "find contradictions and resolve them" implicitly contradicts. Voice fidelity is not a stylistic post-processing step; it's the entire purpose of the voice-skill tree and is downstream of the data layer being rigorous. Privacy/sovereignty is the most defensible non-negotiable here because all four reference systems gesture at it, but the gestures vary in seriousness — Graphify's pipeline-split is the most architecturally credible, AlfredOS's "self-hosted" claim weakens at the LLM layer, and Karpathy's pattern barely addresses it.

## A flag for the closing paragraph

While reading the codebase I noticed that `creek-tools/docs/classification.md` documents phases as **"Origins, Rising, Peaking, Cresting, Receding, Composting"** and modes as **"solo, dialogue, reflective, analytic"** — both of which contradict the canonical spec (which uses Rising/Peaking/Withdrawal/Diminishing/Bottoming-Out/Restoration and Inhabit/Express/Collaborate/Integrate/Absorb). The implementation has drifted from the ontology on the most load-bearing taxonomy in the system. This is not a minor doc fix; it suggests that the wavelength layer hasn't been treated as canonical *in code* the way the spec treats it canonically *in prose*. Several integration candidates downstream (compile-then-query, lint pass, audit report) are downstream of having one source of truth here, so the integration plan flags this drift as a v1 prerequisite rather than ignoring it.
